## Changes affecting aix

- Devin Desktop 3.6.21 (2026-07-29): "Custom subagents can now be defined as flat
  `agents/<name>.md` files, and per-agent directories also accept `AGENTS.md`,
  `agent.md`, and `agents.md`."
   - aix status: follow-up needed, after one verification step. aix currently declares
     Windsurf agents unsupported: `packages/core/src/editors/adapters/windsurf.ts` uses
     `NoAgentsStrategy`, and `packages/schema/src/editor-support.ts` says "aix reports
     configured agents as unsupported for Windsurf." That is now wrong in principle,
     because the product does read file-defined subagents. What is not yet confirmed is
     the discovery path for the Desktop product. The subagent documentation at
     `https://docs.devin.ai/cli/subagents` is written for the Devin CLI and gives
     `.devin/agents/` and `.agents/agents/` at project scope and
     `~/.config/devin/agents/` (`%APPDATA%\devin\agents\` on Windows) at user scope.
     aix's Windsurf adapter targets `.windsurf/` and `~/.codeium/windsurf/`. Confirm
     which directories Desktop reads before writing agent files anywhere.
   - Documented frontmatter, for whenever the strategy is written: `name` (identifier,
     defaults to the file or directory name), `description` (shown to the agent when
     selecting a profile), `model` (override the subagent model), `allowed-tools`
     (restrict the tool set), and `max-nesting` (override the maximum nesting depth).
     Directory layout resolves `AGENT.md`, then `AGENTS.md`, then `agent.md`, then
     `agents.md`.
- Devin Desktop 3.8.20 (2026-08-21): "`mcp_config.json` no longer shows spurious
  'Property is not allowed' warnings."
   - aix status: no change needed, and it likely removes a user-visible complaint about
     aix output. aix writes Windsurf MCP servers to
     `~/.codeium/windsurf/mcp_config.json`
     (`packages/core/src/editors/strategies/windsurf/mcp.ts`). Any aix-written key the
     editor's schema did not recognize would have produced exactly this warning, on a
     file that worked. Nothing about the file aix writes has to change.
- Devin Desktop 3.8.20: "Cascade, Devin Local, and every other ACP agent are now
  unavailable while a workspace is open in Restricted Mode, and hooks no longer load or
  run there." The hooks documentation repeats this: "Hooks do not load or run while a
  workspace is open in Restricted Mode."
   - aix status: no config change needed. This is the Windsurf counterpart to Claude
     Code's safe mode: aix writes the hooks correctly and the editor declines to run
     them. It belongs in the Windsurf notes in `packages/schema/src/editor-support.ts`
     so a user whose hooks never fire has somewhere to look.
- Devin Desktop 3.7.16 and 3.8.20: "Permission rules from different levels (enterprise,
  mode, user, project, subagent) now compose predictably — an explicit `deny:` always
  wins."
   - aix status: no change needed. aix generates no Windsurf permission rules. Recorded
     because it establishes a five-level precedence order that a future portable
     permissions feature would have to match.
- Devin Desktop 3.6.21 fixed "Permission rules written with relative globs (e.g.
  `Read(**/*.pem)`) being pinned to the directory the CLI was launched from."
   - aix status: no change needed, same reason.
- Devin Desktop 3.5.17 (2026-07-17): "The `devin.*` settings for gitignore access,
  completion mode, and auto-continue are now honored."
   - aix status: no change needed. aix writes none of the `devin.*` settings. Worth
     noting only as evidence that the rebrand is reaching the settings namespace, which
     is the direction to watch for a future path change away from `.codeium/windsurf/`.

## Verified unchanged

The hooks documentation still lists the same twelve events and the same four action
fields aix emits. `EVENT_MAP` in
`packages/core/src/editors/strategies/windsurf/hooks.ts` covers all twelve
(`pre_read_code`, `post_read_code`, `pre_write_code`, `post_write_code`,
`pre_run_command`, `post_run_command`, `pre_mcp_tool_use`, `post_mcp_tool_use`,
`pre_user_prompt`, `post_cascade_response`, `post_cascade_response_with_transcript`,
`post_setup_worktree`), and `WindsurfHookEntry` emits `command`, `powershell`,
`show_output`, and `working_directory`, which is the documented set. The three merge
levels (system, user `~/.codeium/windsurf/hooks.json`, workspace `.windsurf/hooks.json`)
are unchanged, and `getGlobalConfigPath` still returns `.codeium/windsurf/hooks.json`.

## Baseline evidence

- `packages/core/src/editors/adapters/windsurf.ts` sets `agentsStrategy` to
  `NoAgentsStrategy`.
- `packages/schema/src/editor-support.ts` records Windsurf agents as an unsupported
  scope.
- `packages/core/src/editors/strategies/windsurf/hooks.ts` holds the twelve-event map
  and `buildWindsurfEntry`.
- `packages/core/src/editors/strategies/windsurf/mcp.ts` sets `globalConfigPath` to
  `.codeium/windsurf/mcp_config.json` and is global-only.
