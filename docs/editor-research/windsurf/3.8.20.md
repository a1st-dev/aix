## Changes affecting aix

- Devin Desktop 3.6.21 (2026-07-29): "Custom subagents can now be defined as flat
  `agents/<name>.md` files, and per-agent directories also accept `AGENTS.md`,
  `agent.md`, and `agents.md`."
   - aix status: no change needed to the Windsurf adapter, and the reason matters more
     than the answer. This entry sits under the changelog's **Devin Local** section, not
     Cascade. Devin Local is the agent that replaced Cascade as Devin Desktop's default
     local agent at the June 2026 rebrand, and the Devin Local documentation states it
     "shares the same agent harness as Devin CLI" and "uses the same skills format and
     discovery mechanism." Its subagents therefore live where the Devin CLI puts them:
     `.devin/agents/` and `.agents/agents/` at project scope,
     `~/.config/devin/agents/` (`%APPDATA%\devin\agents\` on Windows) at user scope.
     Accepted layouts are flat `agents/<name>.md` or a directory whose file resolves in
     the order `AGENT.md`, `AGENTS.md`, `agent.md`, `agents.md`. Frontmatter is `name`,
     `description`, `model`, `allowed-tools`, and `max-nesting`.
   - None of those paths is one aix's Windsurf adapter writes. The adapter targets the
     Cascade surfaces: `.windsurf/` at project scope and `~/.codeium/windsurf/` at user
     scope. Writing agent files into `.devin/` under the `windsurf` editor ID would put
     aix output in a namespace nothing else in that adapter touches, so
     `NoAgentsStrategy` stays for now and the support matrix stays accurate.
- Devin Local reads the config aix already writes. Devin imports rules, skills, and MCP
  servers from other tools by default: "If you don't explicitly configure
  `read_config_from`, all imports are enabled by default." For Windsurf the documented
  import covers rules from `.windsurf/rules/*.md` and `.windsurf/global_rules.md`, skills
  from `.windsurf/skills/` and `~/.codeium/<channel>/skills/`, and MCP servers from
  `~/.codeium/<channel>/mcp_config.json`. Stable reads `~/.codeium/windsurf/`, which is
  the directory aix writes.
   - aix status: no change needed. This settles the namespace question. aix's Cascade
     paths are a supported input to Devin Local, not a stale namespace it ignores, so
     there is no reason to migrate the adapter to `.devin/` or to write both namespaces.
     Doing either would duplicate config that Devin already imports.
- One documented exclusion: "Windsurf workflows are explicitly excluded from import."
   - aix status: follow-up needed, and it is a real gap. aix installs Windsurf prompts as
     workflows, to `.windsurf/workflows/` and
     `~/.codeium/windsurf/global_workflows/`
     (`packages/core/src/editors/strategies/windsurf/prompts.ts`). Rules, skills, and MCP
     servers all reach Devin Local through the import; prompts are the one section that
     does not. Recorded in the Windsurf notes in
     `packages/schema/src/editor-support.ts` so a user who moved to Devin Local knows why
     their aix-managed workflows stopped appearing.
- Devin Local subagents remain outside anything aix writes. There is no Windsurf import
  path for subagents, so they can only come from `.devin/agents/`, `.agents/agents/`, or
  `~/.config/devin/agents/`.
   - aix status: no change needed, and this is why Windsurf agents support is not simply
     a missing strategy. Supporting it would mean writing outside the namespace the
     `windsurf` adapter owns, which is a larger decision than adding a strategy. aix
     already treats `devin` as an alias that normalizes to `windsurf`
     (`packages/schema/src/normalize.ts`), and that alias plan deliberately kept output
     paths unchanged; this finding is consistent with that choice.
- Devin Desktop 3.8.20 (2026-08-21): "`mcp_config.json` no longer shows spurious
  'Property is not allowed' warnings."
   - aix status: no change needed, and it likely removes a user-visible complaint about
     aix output. aix writes Windsurf MCP servers to
     `~/.codeium/windsurf/mcp_config.json`
     (`packages/core/src/editors/strategies/windsurf/mcp.ts`). Any aix-written key the
     editor's schema did not recognize would have produced exactly this warning, on a
     file that worked. Nothing about the file aix writes has to change.
- Devin Desktop 3.8.20: "Cascade, Devin Local, and every other ACP agent are now
  unavailable while a workspace is open in Restricted Mode, and hooks no longer load or
  run there." The hooks documentation repeats this: "Hooks do not load or run while a
  workspace is open in Restricted Mode."
   - aix status: no config change needed. This is the Windsurf counterpart to Claude
     Code's safe mode: aix writes the hooks correctly and the editor declines to run
     them. Added 2026-08-24 to the Windsurf notes in
     `packages/schema/src/editor-support.ts`, so a user whose hooks never fire has
     somewhere to look.
- Devin Desktop 3.7.16 and 3.8.20: "Permission rules from different levels (enterprise,
  mode, user, project, subagent) now compose predictably — an explicit `deny:` always
  wins."
   - aix status: no change needed. aix generates no Windsurf permission rules. Recorded
     because it establishes a five-level precedence order that a future portable
     permissions feature would have to match.
- Devin Desktop 3.6.21 fixed "Permission rules written with relative globs (e.g.
  `Read(**/*.pem)`) being pinned to the directory the CLI was launched from."
   - aix status: no change needed, same reason.
- Devin Desktop 3.5.17 (2026-07-17): "The `devin.*` settings for gitignore access,
  completion mode, and auto-continue are now honored."
   - aix status: no change needed. aix writes none of the `devin.*` settings. Worth
     noting only as evidence that the rebrand is reaching the settings namespace, which
     is the direction to watch for a future path change away from `.codeium/windsurf/`.

## Decision: the windsurf adapter stays on the Cascade namespace

Filed as `aix-xmx`, decided 2026-08-24.

The question was whether aix's `windsurf` editor should follow Devin Desktop from the
Cascade namespace (`.windsurf/`, `~/.codeium/windsurf/`) to the Devin namespace
(`.devin/`, `~/.config/devin/`). It stays where it is.

The premise the question rested on was wrong. Devin's `read_config_from` imports Windsurf
rules, skills, and MCP servers by default, so a Devin Desktop user running Devin Local
does get aix-managed MCP servers and rules; they arrive through the import rather than
from a `.devin/` file aix wrote. Migrating the adapter, or writing both namespaces, would
duplicate config Devin already reads.

What is actually true, and narrower:

- Prompts do not reach Devin Local, because Windsurf workflows are the one surface the
  import excludes. Recorded in the Windsurf support notes.
- Subagents have no Windsurf import path at all, so aix cannot support Windsurf agents
  without writing outside the namespace this adapter owns. `NoAgentsStrategy` is correct
  until someone decides that separately.

This also matches the existing `devin` alias, which normalizes `devin` to `windsurf` and
whose plan explicitly kept output paths unchanged.

## Verified unchanged

The hooks documentation still lists the same twelve events and the same four action
fields aix emits. `EVENT_MAP` in
`packages/core/src/editors/strategies/windsurf/hooks.ts` covers all twelve
(`pre_read_code`, `post_read_code`, `pre_write_code`, `post_write_code`,
`pre_run_command`, `post_run_command`, `pre_mcp_tool_use`, `post_mcp_tool_use`,
`pre_user_prompt`, `post_cascade_response`, `post_cascade_response_with_transcript`,
`post_setup_worktree`), and `WindsurfHookEntry` emits `command`, `powershell`,
`show_output`, and `working_directory`, which is the documented set. The three merge
levels (system, user `~/.codeium/windsurf/hooks.json`, workspace `.windsurf/hooks.json`)
are unchanged, and `getGlobalConfigPath` still returns `.codeium/windsurf/hooks.json`.

## Baseline evidence

- `packages/core/src/editors/adapters/windsurf.ts` sets `agentsStrategy` to
  `NoAgentsStrategy`.
- `packages/schema/src/editor-support.ts` records Windsurf agents as an unsupported
  scope.
- `packages/core/src/editors/strategies/windsurf/hooks.ts` holds the twelve-event map
  and `buildWindsurfEntry`.
- `packages/core/src/editors/strategies/windsurf/mcp.ts` sets `globalConfigPath` to
  `.codeium/windsurf/mcp_config.json` and is global-only.
